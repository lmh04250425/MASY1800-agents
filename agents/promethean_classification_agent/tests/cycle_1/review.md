# Cycle 1 review (v1.0)

All four v1.0 responses passed the frozen validator, and the general technology paragraph stayed the same in every case. Passing the format check did not make the reasoning sound. The review below compares each output with the course instrument (C1, C2) and with the evidence the agent itself listed.

## Preserved failure 1 - overclaim: "Potentially Promethean, Moderate confidence"

The v1.0 classification passed the course's Layer 2 gate when it should have stopped there.

- **The suppression test answered a different question.** C1 asks whether, *if the technology vanished tomorrow*, the old constrained state would simply return. v1.0 answered "increasingly no" by pointing to *uptake*: 31% of developers use agents (E13), and there are 10,000+ MCP servers (E14). Uptake is not dependence. The agent's own sources show that generative AI assists only 1-5% of work hours (E6), that earnings and hours show precise null effects (E9), and that many agent projects are pilots expected to be cancelled (E12). On present evidence, most organizations could go back to human-driven workflows. Under C1 that is a **reduction, so the classification is at most a breakthrough**.
- **Exposure and adoption speed were counted as "widespread impact."** E3 measures *potential* task exposure. E5 and E6 measure *how fast people tried* generative AI. Neither shows a barrier dissolving across sectors. C2 warns that attention is weak evidence, and fast uptake is closely related to attention.
- **The second tier was asserted without evidence.** "Cognitive and social life" was named as a tier, but no source shows that tier reorganizing around *agents*.
- **The label was inherited from a course exemplar.** v1.0 cited the course timeline, where generative AI is marked "Potential Promethean ?" (C1, slide 20), as support. That slide illustrates a different and broader system, and the question mark is part of it. Layer 1 tells the analyst to evaluate the system actually under review.
- **Counter-evidence was listed but never weighed.** E8-E12 appear under contrary evidence, but the classification and the "Moderate" confidence do not respond to them.

## Preserved failure 2 - broad significance turned into advocacy

- In the primary case, v1.0 says the broad significance "supports proceeding with a bounded applicant-support pilot ... rather than waiting" and warns SPS "should not fall behind." That skips the Assignment 3 gate (C3), which compares staff-only work, simple retrieval and the proposed agent *before* any pilot. It also ignores that SPS already runs a public chatbot, Violet (E17), which the output mentions and then does not use as the baseline.
- In contrast 1, the aggressive posture plus the Promethean label produced "the broad significance weighs heavily ... make agentic AI a core differentiator," with no application-level evidence.
- v1.0 never says *how much* the broad significance should count, so the weight cannot be checked and can only grow.

## Preserved failure 3 - hype leaked into the recommendation

The hype probe kept the same label as the primary case. It also correctly rejected the CEO quote, the investment total and the media framing. But it treated two **unverified** claims, a peer school's "AI-first" announcement and a vendor's replacement claim, as "real market momentum." Its recommendation therefore became more aggressive than the primary's: "accelerate ... two-quarter evaluation ... broader rollout plan." The same case plus unverified claims should not produce a different recommendation. v1.0's anti-hype rule named only funding, media, excitement and novelty, so stakeholder and competitor claims were not covered.

## Preserved weakness 4 - one confidence label hid a split

"Moderate" mixed strong capability evidence (E4, E5) with weak or negative realized-impact evidence (E6, E8-E12). Management cannot tell which part is solid.

## What worked and should be kept

- The general paragraph stayed the same across contexts.
- Application significance was judged separately and modestly in every case.
- The hospital case refused patient-facing deployment within 18 months.
- Evidence was dated and attributed.

## Revisions for v1.1 (inputs unchanged; cycle 1 outputs not edited)

1. Answer the suppression test in the **present tense** with dependence evidence. Allow three results: dissolution confirmed, reduction, or *dissolution in progress, not yet testable*. The third result caps the classification at Breakthrough and records an **unresolved** Potential-Promethean candidacy. This is the qualification rule.
2. Add an **evidence admissibility table**: what can and cannot count for each criterion.
3. Report a **floor and a ceiling** with separate confidence levels.
4. Add a **significance-weight scale** (None, Low, Moderate, High) and an **incremental-counterfactual test**: an adoption step is justified only if it would still be justified were the technology merely incremental.
5. Add a **hype-invariance rule**: list every rejected claim, and keep the recommendation identical to the unsteered case unless verified evidence changes.
6. Require tier-by-tier evidence, and do not inherit labels from course exemplars or parent technologies.
7. Name the real application baseline, including the existing public chatbot.

This review was written by the same AI assistant that generated the outputs, so it is not an independent or blinded grade.
